# sidetap

LLM agents drive a real iPhone from Windows over USB + WebDriverAgent (go-ios).
Windows rebuild of ShawnPana/phone-harness (which is macOS-only).

## Architecture

- `src/phone_harness/wda_client.py` — thin HTTP client for WebDriverAgent (:8100). requests only. Kill switch: a `.state/STOP` file blocks every action POST at the `_request` chokepoint (perception GETs keep working). The same chokepoint appends every successful action POST to `.state/agent_activity.log` (bounded ring; typed text NEVER recorded, only char counts — it can be a passcode). WDA holds exactly ONE session and creating a new one evicts the holder, so every client shares the id published in `.state/wda_session`: adopt it, heal an unusable id by adopting the replacement or minting fresh. "Unusable" covers "invalid session" AND the `point.x != INFINITY` state — a session that crosses a screen lock keeps answering GETs but fails every /actions forever (bit the Unlock button live; a test pins the heal). The session creator applies the post-gesture waits from config (WDA_IDLE_WAIT=2, WDA_ANIM_COOLOFF=0 — the cool-off default of 2 cost 2-5s per swipe under scroll momentum; ~0.7s with it at 0, measured on device).
- `src/phone_harness/device.py` — go-ios wrapper; detached tunnel/runwda/forward processes, pids+logs in `.state/`. `ios_path()` falls back to `%APPDATA%\npm\ios.exe` when PATH lookup fails — Windows truncates a >4095-char registry PATH in the logon environment, so shortcut/Startup launches can miss the npm dir (bit the Startup shortcut live; a test pins the fallback). `detect_wda_bundle()` caches its hit in `.state/wda_bundle` because deep sleep EMPTIES `ios apps --list` while the app is still installed (seen live); `lockdown_ready()` (`ios date` exit code) is the "has the human woken the phone" probe — deep sleep gates lockdown (ReadPair errors) while tunnel services keep working. `ddi_mounted()`/`mount_ddi()`: an iOS UPDATE silently unmounts the Developer Disk Image, and without it testmanagerd refuses every test session — runwda dies in dtx channel timeouts that look like a broken tunnel (bit live 2026-08-10); mounting needs the phone UNLOCKED (DeviceLocked otherwise), so `up()` auto-mounts and the doctor names it.
- `src/phone_harness/admin.py` — `doctor` (ordered checks, each names its fix; the STOP kill switch is checked FIRST, then LAN exposure and the 7-day signature countdown), `up` (serialized by `_UP_LOCK`: launch.py's background bring-up and the viewer's Restart link can overlap), `down`, `notify-expiry` (Windows toast when <36h remain on the signature; `--install` registers a daily 10:00 scheduled task via phone-harness.cmd — renewal itself always needs one Sideloadly click, Apple auth mints the profile).
- `src/phone_harness/capture.py` — screenshots. Prefers WDA's HTTP `/screenshot` (sessionless client, cannot steal the one WDA session) with a 10s back-off; falls back to the `ios screenshot` subprocess, which is the only path that works before signing.
- `scripts/lock_ports.ps1` — self-elevating firewall rule blocking LAN access to :8100/:9100 (WDA has no auth). Fired by the viewer's Lock ports button or run by hand.
- `src/phone_harness/signing.py` — `fix-input`: builds a p12 from Sideloadly's cert, captures the profile Sideloadly mints (Temp watcher), re-signs WDA incl. the nested `.xctest` via `ios sign app`. All local; no Apple auth.
- `src/phone_harness/helpers.py` — agent API (`tap`, `tap_text`, `ocr`, `open_app`, …). `ocr()` reads the UI tree; the tree is cached ~2s and every action invalidates it (WDA `/elements` queries were measured SLOWER than `/source` on device — don't reintroduce them). `unlock()` decides from the screen — NEVER from `/wda/locked`, which can report unlocked with the pad on screen (a test pins this): wake + bottom-edge swipe, type PHONE_PASSCODE only if the pad actually appeared, one attempt only (iOS lockout), success = pad gone. It runs on a patient 45s clone of the given client (the first gesture after a deep sleep blocked WDA 20.5s, measured — a 10s client aborts a swipe that still lands), polls for the pad instead of peeking once, and spends exactly one extra wake+swipe when the first burned on a re-slept screen. `send_message()`/`read_messages()` find the thread by TYPING the name into Messages search and tapping the Conversations result cell (bare name, no preview chrome) — never by scrolling the list, whose row taps missed mid-settle and whose top-left "back" geometry is also the list's profile button (both bit live 2026-08-10; `_go_back` now requires a compose bar on screen before tapping). The opened thread's header must still match the contact before anything is typed.
- `src/phone_harness/run.py` — CLI; no-arg mode executes stdin with helpers in scope; autoloads `agent-workspace/agent_helpers.py`; `mcp` subcommand starts the MCP server.
- `src/phone_harness/mcp_server.py` — helpers as native typed MCP tools (`claude mcp add sidetap -- phone-harness mcp`). Registers the helpers functions directly so schemas track their real signatures; `screenshot`/`unlock` get wrappers (bytes return / internal client param), and `act` batches several tool calls into one round trip (whitelisted via `_ACT_TOOLS`; screenshot excluded — bytes don't nest in JSON). Needs the `mcp` package (the one dependency beyond requests).
- `site/` + `api/waitlist.js` + `vercel.json` — sidetap.io marketing site. Static single page wearing the brand tokens from `C:/Projects/animations/brands/phoneclaude.json` (blue = action only, red = STOP only, green = passing checks only); its signature element is a working on-page kill switch. Deploys via Vercel git integration on every push to main (Vercel project `sidetap`, output dir `site/`); `api/waitlist.js` emails Pro-waitlist signups to wes@practicalsystems.io through Resend (`RESEND_API_KEY` lives on the Vercel project, not in local `.env`). Design decisions: `docs/superpowers/specs/2026-08-10-sidetap-website-design.md`.
- `src/phone_harness/viewer.py` + `viewer.html` — human surface: live MJPEG screen (:9100), click-to-tap, drag-to-swipe, keyboard typing, paste box for long text, Notifs/Control edge-gesture buttons, zero-scroll dashboard (NOTHING in the document scrolls; wheel over the phone drives the phone): one-line header (N check dots + count + battery/lock/app glance), permanent columns Actions (text someone / open app, learned+pinned chips), Agent (Activity + Recent sends, hard-capped rows), Phone (passive info), Debug (ast-whitelisted one-liners via /api/console — no eval; entries clamp to 6em; collapsed by default behind a "Debug ▸" toggle with a what-is-this blurb, expand state in localStorage — it exists to run the agent's own helpers when one misbehaves, not for normal control); details live in a single overlay shell (checks, fix-input wizard, full feeds — Escape closes, keydown guard keeps overlay keys off the phone). Overflow policy: hard count caps + degrade-to-fit on render (text-height varies, so count caps alone clipped cards in the adversarial pass — never reintroduce bare caps); checks auto-open the overlay only on an ok→fail transition, once per page load, Unlock/Lock and Restart link buttons, red STOP/RESUME kill switch, red LAN-exposure banner (loud by default; probed in the background) (:8770, VIEWER_PORT to override; 8765 belongs to the Practical Systems API). All `/api/*` calls are origin-guarded against cross-site/DNS-rebinding. Deep sleep kills WDA (~15min after the screen darkens) and NOTHING over USB can wake the phone, so a watchdog thread self-heals: it polls `device.lockdown_ready()` and reruns `up()` the moment the human wakes the phone (cool-down guarded; `/api/unlock` names this exact move when the link is down instead of timing out). Gestures serialize through `_ACTION_LOCK`, and `/api/unlock` passes the viewer's own client into `helpers.unlock(c)` (unlock is timing-sensitive; no session re-discovery mid-wake). The viewer retunes the MJPEG stream whenever the session id changes; gesture waits ride with the shared session (see wda_client.py).

## Commands

- Run everything: `python launch.py` (viewer opens immediately; `up()` runs in a background thread). Double-click equivalents: `sidetap.cmd`, or the Desktop/Start Menu **Sidetap** shortcut (`scripts/install_shortcut.ps1` installs it, `-Startup` adds run-at-boot, icon in `assets/sidetap.ico`)
- Tests: `python -m pytest tests -q`
- Diagnose: `phone-harness doctor` (never guess at connection problems — run this)
- After a replug: the viewer's Restart link button, or `phone-harness up`
- Enable touch input (free Apple ID): `phone-harness fix-input`, then click Start in Sideloadly (mid-week: `phone-harness fix-input .state/profile.mobileprovision` skips Sideloadly; installs need the phone unlocked)
- Never miss the weekly re-sign: `phone-harness notify-expiry --install` (daily toast when <36h left)

## Rules

- Coordinates are points, not pixels. The UI tree and taps use the same units.
- Keep `wda_client.py` free of go-ios knowledge and `device.py` free of HTTP knowledge.
- New agent primitives go in `helpers.py` and must be added to `__all__` (mcp_server.py picks most of them up from its `_TOOLS` list — add there too if MCP-safe).
- No new runtime dependencies beyond `requests` and `mcp` without a stated reason.
- Driving the phone needs the user's hardware set up (docs/setup-windows.md); unit tests must pass without a phone.
